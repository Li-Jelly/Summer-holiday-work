## 析构函数
析构函数（Destructor）是类的一种特殊成员函数，在**对象生命周期结束时自动调用**，用于释放对象占用的资源、执行清理工作
```
class FileHandler{
public:
  FileHandler(const char* path){
    fp=fopen(path,"r");
  }
  ~FileHandler(){
      if(fp)fclose(fp);
  }
private:
  FILE* fp;
};
```
核心特点：
+ 函数名是```~类名```（C++）
+ **没有参数，没有返回值**
+ 一个类只能有一个析构函数（不能重载）
+ 不能显式调用（虽然可以手动调用，但极少这么做）
+ 由编译器在对象销毁时自动调用
### 什么时候被调用
析构函数的调用时机决定了它的行为，主要有这几种情况：
1. **栈对象离开作用域**
```
void func(){
  FileHandler f("a.txt");
}      //离开作用域，F的析构函数在此调用
```
2. **栈对象被delete**
```
FileHander*p=new FileHandler("a.txt");
delete p;    //调用析构函数+释放内存
```
3. **临时对象表达式结束**
```
doSomething(FileHandler(a.txt));//临时对象在语句结束后析构
```
4. **容器/数组成员销毁**
```
{
    std::vector<FileHandler> v;
    v.push_back(FileHandler("a.txt"));
}   // 容器销毁时，每个元素的析构函数被调用
```
5. **程序结束时，全局/静态对象析构（顺序与构造相反）**
### 为什么需要析构函数：RAII
析构函数最重要的价值是支撑RAII（Resource Acquistion Is Intialization,资源获取即初始化）这一C++核心思想：
+ **构造函数**获取资源（内存、文件、锁、socket、数据库连接）
+ **析构函数**释放资源
这样资源释放与对象声明周期绑定，即使发生异常、提前return，也能保证资源被释放，避免泄露
```
class MutexLock {
public:
    MutexLock(std::mutex& m) : m_(m) { m_.lock(); }
    ~MutexLock() { m_.unlock(); }   // 无论怎样退出，锁都会释放
private:
    std::mutex& m_;
};
```
标准库里的````std::vector``` ```std::string``` ```std::unique_ptr``` ```std::lock_guard```都依赖析构函数实现自动内存/资源管理
### 析构顺序
成员析构顺序与构造顺序相反，且一定是：
1. 先执行析构函数体本身
2. 再按成员声明顺序的逆序析构各成员
3. 最后析构基类子对象
```
class C {
    A a;   // 先声明
    B b;   // 后声明
};
// 构造顺序：a → b
// 析构顺序：b → a
```
注意：成员的析构顺序只取决于**声明顺序**，与初始化列表里的书写顺序无关。
### 虚析构函数（重点）
这是析构函数最容易出问题的地方。
```
class Base {
public:
    ~Base() { }          // 非虚
};
class Derived : public Base {
public:
    ~Derived() { }
};

Base* p = new Derived();
delete p;   // 危险！只调用 Base::~Base()，Derived 部分资源泄漏
```
**规则：如果一个类会被作为多态基类使用（有虚函数），那么它的析构函数必须是虚函数**
```
class Base {
public:
    virtual ~Base() = default;   // 正确
};
```
这样```delete p``` 时会先调用```Deriver::~DERIVED()```,  再调用```Base::~Base()```
反之，如果类**不打算被继承**，就不要写虚析构（会引入vptr开销），可以用```final```明确禁止继承
### 纯虚析构函数
有时想把类设计成抽象基类，但又需要一个析构函数体：
```
class Base {
public:
    virtual ~Base() = 0;   // 纯虚析构
};
Base::~Base() { }          // 必须提供定义！
```
纯虚析构函数是合法且有用的：它让类成为抽象类，但派生类析构时仍会调用基类的这个定义。
### 析构函数中的异常
析构函数不应抛出异常。原因：
+ 如果析构在栈展开（异常传播）过程中被调用，此时再抛异常会导致 std::terminate。
+ 标准库容器（如 vector）在销毁元素时假设析构不抛异常。
如果清理逻辑可能失败，应在析构函数内部捕获并处理（记录日志、吞掉异常），而不是向外抛。
### 常见陷阱
1. **析构函数中调用虚函数**
在基类析构函数执行时，派生类部分已经被销毁，此时虚函数调用会退化到基类版本，不会产生多态行为。所以不要在析构函数里调用虚函数。
2. **浅拷贝导致的 double free**
如果一个类管理资源但没写拷贝构造/拷贝赋值，默认的浅拷贝会让两个对象持有同一指针，析构两次导致崩溃。这就是 Rule of Three：需要析构函数时，通常也需要拷贝构造和拷贝赋值（C++11 后扩展为 Rule of Five，加上移动构造和移动赋值）。
3. **delete 不匹配**
```new[]```必须配```delete[]```，否则数组元素的析构函数不会全部被调用
```
Base* arr = new Derived[10];
delete[] arr;   // 若 Base 析构非虚，行为未定义
```
4. **手动调用析构函数**
只有在用 placement new 等特殊场景才手动调用 p->~T()，普通情况下交给编译器。
