## 多媒体内容
通过四个层面来认识计算机领域的多媒体内容：**物理层（二进制）**、**编码层（格式）**、**语义层（内容理解）**、**生成层（AI运算）**
---
### 二进制
计算机里没有“图片”、“文字”、“视频”的概念，只有**比特（0/1）**  
存储介质（硬盘、内存、SSD）本质上只区分两种物理状态：
+ 磁性方向/电荷有无/电压高低
+ 对应0/1
**关键点**：同一串```01000001```，按ASCII解释是字母```A```，按整数解释是```65```，按颜色解释可能是某种红色分量
**意义来自约定，而不是比特本身**
### 三种媒体的编码方式
#### 1. 文本
**最直接**：字符->数字->二进制
+ Unicode（统一所有字符的编号）：**“字典”**，给世界上每个**字符**（字母、汉字、emoji等）分配一个唯一的**编号**，比如“汉”是```U+4F60```
+ UTF-8（让编号能高效、兼容地存储和传输）:**“规则”**，把上面的编号翻译成二进制的**规则**
  + **变长**（最常用的特点）：英文1字节，汉字3字节，emoji4字节
  + **兼容ASCII**：英文文本存成UTF-8和ASCII完全一样，老程序不会乱码
  + **节省空间**：英文只占1字节，比用固定2或4字节的编码省很多
  + **无字节序问题**:不像UTF-16/UTF-32有大小端困扰
    + 以整数```0x12345678```（十六进制）为例：
      + 高位字节：0x12
      + 次高字节：0x34
      + 次低字节：0x56
      + 低位字节：0x78
    + **大端**（高位字节排在低地址——前面）：```地址:  1000  1001  1002  1003  内容:  12    34    56    78```
      + Motorola 68000、PowerPC、网络协议（TCP/IP 规定用大端传输，叫"网络字节序"）
      + 和手写顺序一样
    + **小端**（低位字节排在低地址——前面）：```地址:  1000  1001  1002  1003  内容:  78    56    34    12```
      + x86、x64、ARM（默认小端）
      + 优势是低地址取低位字节，某些运算更方便
  + **自同步**：从任意位置都能较快找到字符边界，适合网络传输
+ **本质**：文本是**离散符号序列**，每个符号都有确定的编码，无需“还原”，直接查表
  + ```中``` = U+4E2D = UTF-8 编码 ```11100100 10111000 10101101```
>>文本最“干净”：比特-字符一一对应
#### 2. 图片
**核心思想：把连续的光信号离散化采样**
##### 1. 位图（Raster）
+ 把画面切成**像素网络**，如1920*1080
+ 每个像素用数字表示颜色：
  + RGB：3个通道，每通道0–255（8 位），共 24 位
    + R红色：RGB(255,0,0)=```11111111 00000000 00000000```纯红色
    + G绿色：RGB(0,255,0)=纯绿色
    + B蓝色：RGB(0，0，255)=纯蓝色
    + RGB(255,255,255)=白色
    + RGB(0,0,0,)=黑色
    + 一张 1080p 未压缩图 = 1920×1080×3 字节 ≈ 6 MB
    + 所有会发光的屏幕都使用 RGB，网页设计底层都是 RGB 数据。
    + 和印刷用的 CMYK（青、品红、黄、黑）模式不同，**CMYK 是靠反光呈色**，适合印在纸上
+ **压缩**：
  + **无损（PNG）**：找重复模式，用更短编码
  + **有损（JPEG）**：利用人眼对亮度敏感、对色度迟钝，丢弃高频细节。这就是为什么 JPEG 会有"块状伪影"
##### 2.矢量图（Vector）
+ 不存像素，存几何指令："画一个圆心(100,100)半径50的红色圆"
+ 缩放不失真，SVG 就是 XML 文本
#### 3.视频
**本质 = 快速播放的图片序列 + 声音**
+ **关键压缩思想：帧间冗余**
  + I 帧（关键帧）：完整图片，像 JPEG
  + P 帧：只存"相对前一帧的变化"（运动补偿）
  + B 帧：参考前后帧
+ 一段 1080p 视频未压缩：1920×1080×3×30 ≈ 186 MB/秒！所以必须靠 H.264/H.265/AV1 这类编码压缩到几 MB/秒
+ **音频**：按时间采样（如 44.1kHz），每个采样点存振幅（16 位），再压缩（MP3/AAC）
>> **统一规律**：媒体编码 = **采样离散化** + **压缩去冗余**。人眼/人耳不敏感的部分被大胆丢弃。
### 解码与渲染
播放/显示时发生的事：
```
二进制文件
  → 解码器（按格式规则还原）
  → 内存中的像素数组 / 音频波形 / 字符缓冲区
  → GPU/声卡/显示器 转换为物理信号
  → 你的感官
```
+ 图片：解码器还原出像素矩阵 → GPU 写入显存 → 显示器每个像素发光
+ 视频：解码器逐帧还原（含运动补偿计算）→ 按时间轴送显
+ 文本：字体引擎把字符码位映射到**字形轮廓**（矢量）→ 光栅化成像素 → 显示
**具体是渲染出来的，不是存储的。** 文件里只有数字，屏幕上的画面是硬件实时重建的。
### 内容如何参与运算与生成
这是最大的范式转变。传统方式是人写规则，AI 方式是从数据中学规则。
#### 1. 内容必须先变成"向量"
AI 不能直接吃 JPEG 或文字，要把它们转成数字向量（张量）：
+ **文本**：分词 → 每个词查 embedding 表 → 变成如 768 维向量。语义相近的词，向量也相近
+ **图片**：切成小块（patch）→ 每块拉平 → 线性投影成向量（ViT 做法）
+ **视频**：帧 patch + 时间位置编码
此时，**文字、图片、视频都统一成了同一空间的向量**。这就是多模态的基础——猫的图片和"猫"这个词，向量可以很接近。
#### 2.运算的核心：矩阵乘法 + 注意力
+ **神经网络**本质是海量**矩阵乘法** + **非线性激活**
+ **Transformer 的注意力机制**：让每个向量去"查询"其他向量，决定关注谁
  + 公式：```Attention(Q,K,V) = softmax(QKᵀ/√d)·V```
  + 直观：计算"相关性权重"，加权求和
+ 一个 GPT 类模型有几十亿到上万亿参数，生成每个词都要做上千亿次乘加运算
#### 3. 生成是怎么回事
##### 1.文本生成（自回归）
```
输入"今天天气" → 模型输出概率分布 → 采样出"真" → 
"今天天气真" → 再预测 → "好" → ...
```
每次预测下一个 token，循环往复。没有"理解"，只有条件概率。
##### 2.图片生成（扩散模型为主）
+ **训练**：给图片不断加噪声，让模型学"如何从噪声中还原"
+ **生成**：从纯随机噪声开始，模型一步步**去噪**，逐渐浮现出图像
+ 文本提示通过**交叉注意力**注入，控制去噪方向
+ 本质：在像素/潜空间向量上做迭代运算
##### 3.视频生成
+ 在图片扩散基础上加**时间维度**，保证帧间连贯
+ 计算量巨大：要同时处理空间和时间的一致性
**AI 生成的内容，本质上是在高维向量空间里做概率采样，再解码回像素/字符。** 模型"记住"的不是原图，而是数据的统计规律（分布在几千亿参数里）
### 总结
```
物理层：    0/1 电平
              ↓ 约定
编码层：    字符码 / RGB像素 / 帧序列  （+压缩）
              ↓ 解码渲染
感知层：    屏幕像素 / 声波 / 字形
              ↓ 编码为向量
语义层：    embedding 向量（多模态统一空间）
              ↓ 矩阵运算 + 注意力
生成层：    概率分布 → 采样 → 解码 → 新内容
```
